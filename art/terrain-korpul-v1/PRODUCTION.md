# Kor’Pul 196格图生产与验收

2026-09-27。完成196张128×128 RGBA完整复合PNG，位于 `data/gfx/refined/korpul/`。精确路径、mask、parity、hash、源母版及几何在 `runtime-manifest.json`。美术代理未修改运行Lua/ready、未启动游戏、未提交；主代理负责实机、启用、打包与提交。

## 补件与来源

继11次概念生成后新增5次独立内置ImageGen，共16张原始输出全部保留：

- `wall-top-v1`：没有孤立块外缘的浅色多块连续砌石顶面。
- `hardwall-top-v1`：少缝冷灰大板连续顶面。
- `door-leaf-horizontal-v1`：固定左上光、东西向木门扇。
- `door-leaf-vertical-v1`：初版铰链在北端，与所需南端枢轴不符，拒选并保存。
- `door-leaf-vertical-v2`：仅把铰链移至南端、拉环移至北端，几何和世界光向保留。

原有 `wall-v1` / `hardwall-v1` 含可用的四个真实方向边缘，故不额外随机生成八条边带。工程只从各自对应的北/东/南/西像素区域取样，按固定矩形缩放/遮罩拼接；没有旋转、镜像、程序清除明暗或程序噪声。采样坐标在C文件 `edgecrop()`，并记录在 `production-components.json`。门框也使用同一砌石顶面与同向边带，横纵框截面使用相同20×40尺寸，开闭共享同一几何函数。

全部新增母版1254²，工具源路径、完整提示词、hash、原生alpha边界见prompts。运行源共8张：两地板、两连续顶面、两孤立块边带来源、两定向门扇。原始母版不覆写。

## 确定几何与连接

墙体占满128规则格。若连接位为1，该边没有外露边带，连续顶面延伸至格边；位为0时保留本格内2px北/西边、5px东侧、9px南侧厚度。所有RGB纹理来自ImageGen，矩形遮罩只决定现有规则格的几何。四边均不连接也不会留环状可走地板缝；mask15没有外露侧面。普通/硬墙共享高度和格边，保留材料差异。

门框、门扇坐标均固定于整格，不按每张alpha居中。水平框连接E/W，垂直框连接N/S；垂直于门轴的邻墙位不能在开口里创造挡路构件。门框与邻墙连接端直达格边，邻墙本身也占满本格，不产生地板细缝。无连接时端部向内收4px。闭门门扇横断相应通路，开门旋开后的定向门扇置于侧边；两张定向画作各保持原来的世界光，不旋转烘焙像素。偏向南侧/西侧的门轴为门扇在单格内摆放留出空间，中央大面在开门时通畅。

运行每格先铺地板，再合成材料/边带/门扇。地板格线仅在本格内，并处于构件下方；parity1统一乘0.90，parity0原值。A/B仅纹理变化，同通行语义。运行RGBA全部alpha255，源部件alpha原样参与合成。四位mask不推断对角内角，不新增斜切几何。

## 实际开图审阅

已用本地浏览器、deviceScaleFactor=1捕获并实际打开：

- `review/runtime/wall-masks.png` 与 `hardwall-masks.png`：每图16mask、两套parity、混普通/硬墙邻居，真实48px。
- 四张 `review/runtime/door-*-masks.png`：两门轴/开闭状态全部16mask与双parity，真实48px。
- `review/runtime/production-sheet.png`：全部材料48/64/96px、灰度、4×4实心普通墙、直线/转角/T/十字/混材、东西向与南北向单格窄道、两种门轴、对角接触。

观察：4×4普通墙内部是连续砌石材料，没有地板沟槽或假走廊。普通/硬墙在48px靠多块/少缝大板和主要明暗区分；深边只在真正外露边。开门中央通路明确，闭门木条跨过对应路线；横纵门扇厚度接近，未再出现概念稿的纵门过细比例。两parity可读但不会新增地形规则。大面积砌石仍能看出纹理重复，这是材质复用，并非路径标记。

第一轮机械组合曾给孤墙留5px地板边，在门接墙处会像细走廊；该几何已修为整格占满后重新导出审阅。概念阶段的3次拒选和生产门扇铰链返修均保留。没有伪称这些静态图是实机。

## 机器验证与复现

从插件仓库目录执行：

```sh
node tools/export_korpul_terrain.cjs --review
```

脚本编译C导出器到临时路径，机械合成全部196文件，检查精确文件集合、PNG尺寸/色型，写manifest和静态审图；生成后删除临时二进制。无网络、无游戏或存档操作。

实际只读解码检查：196张均128² RGBA且alpha全255、全部manifest hash匹配；墙顶内部像素不随mask变化；门的非轴向邻接位不会添加障碍。结果 `review/runtime/validation.json`。两个构建器源码hash进入manifest，来源母版hash逐项记录。

此时可交主代理执行真实DEFAULT/HIDEOUT、开关门、挖掘、FOV/记忆、未知格回退、存档/克隆及演员覆盖审阅。只有主代理的最终实机和打包清单通过后才启用发布ready；196文件存在本身不替代这些行为测试。
