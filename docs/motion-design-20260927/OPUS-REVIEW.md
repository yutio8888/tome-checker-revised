# 棋子运动视觉方案（设计评审：Opus 5.5）

**看过的材料和边界：** 我看了7张关键帧原图（walk‑1000/1040、special‑600/840、rush‑920、twitch‑off‑480、path‑camera‑1160）、`wolf.png`原图、Astra的README和summary.json，还读了`src/map.c`（setMoveAnim、blur、twitch）、Entity和ToME原版Actor的move/knockback/pull/forceMoveAnim，以及插件的overlay回调。五段APNG动图我没有逐帧播放，下面关于动态的判断都来自关键帧、遥测和源码。所有数字都是建议起点，没有实测调优过。主代理的overlay blur=0修复我按"未验证"处理。

## 源码里查到的四个约束（决定了能设计什么）

1. **主体的轨迹没法做缓动。** C层按30关键帧/秒线性插值。smooth=3时，中间只有1/3和2/3两个位置。twitch的系数按三角波算，这两个位置都是2/3，所以实际是两帧抬高0.10格的平台，0.15格的配置峰值永远取不到，这和Astra实测的0.10一致。所以本方案的缓动曲线只适用于插件自己用毫秒时钟画的程序层，主体一律用原生线性插值。
2. **overlay回调收到两套坐标。** `x,y`含twitch抬升，`tlx,tly`贴地面。现在环、盾和角标用的是`tlx,tly`，这就是"盘子抬起来、环留在地上"的原因，只改一个参数就能统一。
3. **twitch_dir支持8个方向。** 起点等于终点时，`setMoveAnim(self.x,self.y,speed,0,dir,amp)`只产生朝dir方向出去再回来的纯位移，不需要C改动，也不需要新帧，就能做近战前冲。原版选项文案写着"moving and attacking"，但我在`tome/class`里没找到攻击时触发twitch的调用，也就是说现在近战没有任何动作。
4. **blur只影响画面，不影响时长。** 它只画历史副本，而且是满不透明度，时长由move_max决定。所以主体blur改成0不会改变节奏。另外Haste、Celerity、lightning_speed下的**普通步**原生也带blur 2到3，会出现同样的整枚副本。

## 1. 推荐的运动视觉语言："一枚硬币棋子，三种移动"

**推荐轻抬，不推荐纯滑移。** 棋子的本体、血环、护盾和角标作为一个整体一起抬起。理由：
- 用户已经定了"普通移动用原版插值加起伏"，默认twitch=true，轻抬是零成本、零规则风险的现成资源。
- smooth=3的实际效果是"拿起、平移两帧、放下"，本身就是缩小版的桌游挪子。起伏只有0.10格，不会被误读成路径偏移。**不应加大幅度。**
- 轻抬最大的价值是和"贴地滑行"形成对比，从而区分"自己走"和"被推动"。纯滑移会丢掉这一层含义。
- 玩家关掉原生twitch后，整个系统自然退化成纯滑移，这就是减少动态的路径，不需要额外开关。

三类移动的语义：

| 类别 | 画面 | 适用场景 |
|---|---|---|
| **拿起放下** | 整枚轻抬0.10格，平移后落回，无尾迹 | 普通步、斜行、寻路、加速步 |
| **贴地疾滑** | 不抬起，只有一张棋子图，身后一道深色半透明擦痕 | 冲锋/Rush、击退、拉拽、快速强制位移 |
| **离座入座** | 没有路径；原位留一个空位环，目标位置棋子入座 | 普通传送 |

另外加一个不移动的动作：**近战前冲**，朝目标方向短促探出再回位。

固定规则：
- 任何时刻只有一枚完整棋子。
- 程序层绝不使用阵营色或护盾珍珠白，避免被读成单位或状态。
- 所有效果都是即发即忘，不等待、不排队、不锁输入。

## 2. 各类动作的具体参数

时长按30关键帧/秒换算；幅度的单位是格。

| 动作 | 时长 | 轨迹和幅度 | 缓动 | 层与特效 |
|---|---|---|---|---|
| 普通单步 | 原生3关键帧，约100ms | 直线；twitch方向8（向上），平台约0.10 | 原生线性 | 主体和状态层一起抬（见第3节）；无尾迹 |
| 连续快速输入（上一动画未完成时再输入） | 原生，从当前绘制位置接续 | **可选修正**：插件自己记录上次开始时间，还在动画中就对本步传twitch=0，峰值从约0.167降到不超过0.10，只会单调落回 | 原生 | 不排队、不回弹；寻路每步间隔约180ms，每步都会完整一跳，这是想要的效果 |
| 斜行 | 同普通单步 | 对角直线加竖直抬升（保持方向8，不做斜向起伏） | 原生 | 同普通单步 |
| 近战前冲（新增） | 4关键帧，约133ms | 用twitch朝目标方向；正交方向幅度0.12，斜向0.09（C对x、y各加一次，合成长度约0.127）；轨迹0→0.06→0.12→0.06→0 | 原生三角波 | 整枚一起动；受原生`twitch_move`开关控制；只在攻击者对玩家可见时触发；同一攻击者150ms内只触发一次（多段攻击、横扫）；如果身上已有未完成的强制位移（例如Rush末段），跳过 |
| 冲锋/Rush、forceMoveAnim | 原生8关键帧，约267ms | 贴地直线，不抬起 | 原生线性 | 棋子模式下主体blur改为0（可配置，见第4节），状态层只画一次；擦痕从起点格中心拉到棋子边缘（离中心0.45格处截断）；到达时如有攻击，由近战前冲接上（这里会因上面的规则跳过，保持干净） |
| 击退 | 原生9关键帧，约300ms（原生会先reset，这点不变） | 同Rush | 同上 | 擦痕同上；落地后250ms淡出（ease‑out），总长不超过约550ms；撞墙没有产生位移时不画 |
| 拉拽 | 同击退（原生也是9和5） | 同击退 | 同上 | 擦痕同上，方向本身就说明谁被拉向谁 |
| 普通传送 | 瞬切 | **不画任何连线** | 程序层：ease‑out | 原位（仅当原位对玩家已见时）：中性灰（约160,160,150）虚线环，8段，直径从0.8格收到0.56格，透明度从0.35降到0，共300ms。目标位置：环、盾和角标整体从1.15倍缩到1.0倍，150ms，主体不缩放 |
| 带force_move_anim的传送 | 原生8关键帧滑行（调用方明确要快速位移） | 贴地 | 原生 | 不画擦痕，因为连线可能穿墙，会暗示走过中间格 |

**擦痕规格：** 颜色为黑色，靠近棋子一端透明度0.30，渐变到起点端为0；宽度在棋子端取max(1px, 0.10格)，在起点端收细到0.04格。经过其他可见单位所在的格子时，那一段不画，避免像是在别的棋子身上划了一道。

## 3. 状态层、底座、阴影、光照和镜像

- **血环、护盾、角标：随盘，不留在地面。** overlay回调和本体回调的后备路径（Actor.lua:120附近的small/bigTacticalFrame和说话气泡）统一改用含抬升的`x,y`。
  - 理由：棋子图是带铜边的硬币（`wolf.png`就是浮雕章），环在视觉上就是硬币的边缘。分离会让烘焙底座露出环外，形成双影。
  - 地面锚点的作用在100ms内没有意义，停稳后两套坐标完全一样。快速反向时`tly`本身也会上移约4.3px，本来也不是可靠的地面参考。
  - 语义不变：12点起逆时针、四种关系色、护盾珍珠白、rank 3.2以上才有角标、normal/elite无标记。
- **底座和阴影：** 不新增接触阴影。原因有两个：接触阴影必须画在主体下层，而overlay在z+1，需要新开一层，有风险；100ms的平台抬升也不需要它。烘焙底座保持原样。
- **镜像：默认固定朝向，棋子模式下不翻转；提供"跟随移动（原生）"选项。**
  - 理由：硬币不会镜像；`wolf.png`的光源在左上，翻转后变成右上，满盘棋子的光照方向会不一致；朝向不是ToME的规则。
  - 朝向带来的生气，改由轻抬和近战前冲来补。
  - 做法是superload `MOflipX`，只对拥有棋子的actor生效，并记录`_flipx`，保证切回原版不受影响。
  - 如果以后坚持保留翻转，唯一干净的做法是把人物和底座拆成两层，只翻人物，这属于第5节的美术包。

## 4. 配置和减少动态

原生的smooth和twitch仍然管拿起放下和整体速度，插件不覆盖它们。插件新增以下设置：

| 设置 | 选项 | 默认 |
|---|---|---|
| 特殊位移尾迹 | 擦痕 / 原生重影 / 无 | 擦痕 |
| 棋子朝向 | 固定 / 跟随移动 | 固定 |
| 近战前冲 | 开 / 关（原生twitch关闭时一并失效） | 开 |
| 传送离座入座标记 | 开 / 关 | 开 |
| **减少动态效果** | 开 / 关 | 关 |

打开"减少动态效果"后：
- 关闭近战前冲和入座缩放；
- 擦痕和空位环不做动态变化，只做150ms淡出；
- 尾迹被强制设为"无重影"；
- 在说明文字里建议同时关闭原生twitch，但不自动修改原生设置。

所有选项都只影响绘制，不改变能量、回合、逻辑位置、AI或输入时序。

## 5. 最小可验证工作包

**纯程序实现，不需要新增任何美术：**

| 包 | 内容 | 验收 |
|---|---|---|
| WP0（主代理进行中） | overlay blur=0 | special和rush中间帧只有一套环、盾、角标；主体重影仍在；停稳帧和修复前逐像素一致；时长不变 |
| WP1 整体抬升 | 回调改用`x,y` | walk中间帧环心和本体中心差0px；twitch关闭时画面不变；快速反向时两者偏移相同 |
| WP3 固定朝向 | 包装MOflipX，并加配置 | 左右移动不翻转；切换到"跟随移动"后恢复原生；非棋子actor不受影响；读档后状态正确 |
| WP5 擦痕 | 棋子模式主体blur=0，加程序擦痕；覆盖Haste普通步 | 任一帧只有一枚完整棋子；起点在迷雾中时不画；10fps下至少有1帧能看到擦痕 |
| WP4 近战前冲 | hook攻击入口，用twitch_dir实现 | 前冲峰值约0.12格，最后精确回到格心；能量和回合日志与关闭时一致；不可见攻击者不触发 |
| WP6 传送标记 | superload teleportRandom | 没有中间格路径；原位在迷雾或未见格时不画 |
| WP2（可选） | 接续步twitch=0 | 快速反向峰值不超过0.10；独立单步仍是0.10 |

**测试矩阵（每个包都跑）：**
- 格子尺寸：48、64、96px。0.10格分别约等于4.8、6.4、9.6px；线宽下限1px。
- HUD：tome-board-hud 0.2.4的Board和Minimalist两种布局。检查点：只在`on_map`时绘制，头像、HUD不受影响。
- 帧率：10、30、60fps。10fps时一步是瞬移，这时毫秒时钟驱动的擦痕和标记正好补上方向信息。
- 迷雾：起点、终点分别在可见和不可见两种情况。
- 着色器：开和关。

证据格式沿用Astra的做法：APNG加逐帧TSV，TSV记录本体、overlay和环的位置。

**确需美术资源的只有WP7（可选）：** 审计37款棋子的光照方向。如果选择保留翻转，就把左右不对称的棋子重新打光到正上方，或者拆成人物和底座两层。**任何怪物都不需要画走路帧。**

## 6. 成本、风险和执行顺序

| 包 | 成本 | 主要风险 |
|---|---|---|
| WP1 | 很小，几行 | 几乎没有 |
| WP3 | 小 | 会有部分棋子看起来"背着走"，靠配置兜底 |
| WP5 | 中 | 擦痕和其他格子的绘制顺序可能冲突；只对棋子actor生效，需要判断归属 |
| WP4 | 小到中 | 攻击入口很多（横扫、反击），靠节流和"强制位移中跳过"两条规则控制 |
| WP6 | 中 | 传送入口不止teleportRandom，首版只覆盖它 |
| WP2 | 小 | 收益也小 |
| WP7 | 大 | 美术返工量大 |

**建议顺序：** WP0验收 → WP1 → WP3 → WP5 → WP4 → WP6 → WP2（可选）→ WP7（可选）。

前三步做完，就能看到"单一棋子、整体抬升、统一光照"的桌游质感，风险最低。WP5和WP4带来最主要的"有趣且易懂"：一眼看出谁被推、谁冲锋、谁打了谁。所有改动都不需要改C，也不涉及规则。
