# 随机怪原始身份记录 — 2026-09-27

`createRandomBoss` 现在只给**生成前已经精确识别、生成结束时身体仍相符**的实例记录 `_checker_token_origin`。棋子按这个记录认回原始身体；名称、unique、define_as 和 rank 保持原生结果。普通身份仍走原有精确匹配，Party 的 `"player"` unique 哨兵仍须由渲染集成确认真实队伍／控制历史后放行。

此轮没有新增或重排 catalog，美术覆盖仍由 catalog 决定。GameState 中原来固定 Trollmire 地形版本的 debug override 已移除，本文件仅保留随机身份 hook。

## 生命周期和边界

本仓库原生源码 `game/modules/tome/class/GameState.lua`：

| 原生位置 | 行为 | 处理 |
| --- | --- | --- |
| 1585–1590、1591–1639 | entityFilterPost 把普通怪交给随机 Boss／rank 3.2 rare 生成 | 不改过滤器或生成参数 |
| 2368–2374 | `base:clone()`，随后 init、rnd_boss_init | 在调用原生函数之前从 base 捕获精确身份 |
| 2388–2400 | 改写 name、unique、define_as；设置原生 rank | 不解析名字后缀，不按 subtype 推断，不修改这些字段 |
| 2423–2427 | 初始化 body／背包，再 resolve | 等待原生处理完成 |
| 2475 | 应用随机职业与相关数据 | 不包装／替换职业生成 |
| 2477–2516 | 安装进入关卡后的回调 | 保持原回调；后续每次识别仍重新检查身体 |
| 2534–2536 | post 回调，返回 actor 和 boss_id | 回调结束后检查最终外观，再记录原始身份；保留两个返回值 |

`engine/Zone.lua:631` 的 finishEntity 会再次 clone，`:735–747` 设置 combat 自引用并最终 resolve。身份标记是普通平面表，原生 clone 会复制；后续身体若被 resolve、talent、变身或第三方显示改掉，识别会回退。原生 `engine/class.lua:223` 实现 clone，`:443–479` 实现 save；`Entity.lua:213` 加载时会重分配 uid，因此 uid 不作为持久身份。

身份 hook 只写返回实例的 `_checker_token_origin`，不改 base、data、攻击、AI、天赋、生命、掉落、背包、rank、派系或其他规则字段。未取得有效生成前证据时会清掉返回实例继承的旧标记，防止把旧随机身份重新用作新生成的凭据。递归生成各自持有局部捕获记录；原生错误照常抛出。

## 标记契约

版本 1 的 `_checker_token_origin` 只含字符串、数字和布尔值：

- `version=1`、`source="createRandomBoss"`、catalog `id`。
- `base_name`、`base_image`、`base_type`、`base_subtype`、`base_define_as`：必须与当前 catalog 条目完全一致；普通条目的 define_as 用 `false` 表示缺省。
- `appearance`：已验证的 `single` 或固定已知 Boss 的 `native-tall`；五个原生显示尺寸 `display_w/h/x/y/scale` 以缺省值归一化，记录之后的尺寸变化也会回退。
- 生成完成后的 `name`、`define_as`、`unique`，以及实例上的 `randboss==true`，共同约束生成身份。已有经验证的 Party 控制路径可以把 unique 临时变为 `"player"`。

不保存 display、Entity、嵌套表、函数、userdata、rank、faction 或 uid。版本不符、缺字段、额外字段、元表、未知 id、非有限尺寸和 catalog 签名改变都会拒绝。每次识别重新检查 replace_display 所有权以及 moddable_tile、shader、anim、add_displays、textures、shader_auras、add_mos 和 tall 图层限制。临时外观变化时保留标记，外观恢复后可再次使用。

这是一份可查验的生成来源记录，不是安全认证系统；有权任意改写 actor、catalog 和插件代码的另一个插件也能伪造全部数据。它针对过期、缺失或损坏字段，以及现实中的身体／显示变更进行保守拒绝。

## 公共识别接口

`Tokens.identify(actor, owned_display, allow_player_identity)` 仍返回 id 或 nil。`Tokens.explain(...)` 使用完全相同的判断并额外返回 reason，供覆盖审计复用。

| reason | 含义 |
| --- | --- |
| `exact-identity` | 已知的精确原生身份 |
| `random-origin` | 经生成前捕获、生成后验证的已知原始身体 |
| `no-art` | 无已知普通身份素材 |
| `unknown-unique` | 未知 unique；不能因相同图像或 subtype 取得棋子 |
| `identity-changed` | 精确名字命中，但 define_as 不同 |
| `body-changed` | 类型／身体图像不符，或随机身份的外观形态／尺寸改变 |
| `external-display` | replace_display 不是调用方持有的显示对象 |
| `moddable-tile` / `shader` / `animation` | 外观系统需原生显示 |
| `add-displays` / `textures` / `shader-aura` / `add-mos` | 额外显示层需原生显示 |
| `native-tall-changed` | 固定已知 Boss 的 tall 图层不再满足已验证形态 |
| `invalid-origin` | 标记格式、版本或 catalog 身体签名不正确 |
| `stale-origin` | 实例的生成身份或 randboss 状态已不匹配标记 |
| `invalid-actor` | 输入不是 actor 表 |

reason 说明首次决定性的拒绝原因。外部 display 优先；没有可以建立的身份时，不会再把未知怪的 shader 等信息当作“已有素材因外观被拒绝”。有效精确身份不依赖旧随机标记，因此普通身份不会被无关旧字段污染。

`captureRandomOrigin(base)` 仅捕获精确身份，不接受另一个随机身份标记作证据。`recordRandomOrigin(actor, capture, boss_id)` 验证并复制捕获表，写入最终记录。两者由 production GameState hook 成对使用；审计应调用 explain，避免重建这套规则。
