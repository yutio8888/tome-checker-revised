## 数字依据与估算步骤

1. [全资产盘点](<workspace>/documentation/board-visual-audit-2026-09-26/report.md)记录本体NPC主图库645文件，含三DLC为835；本次核对对应精确像素去重为642和832。地形主图库2797/4154文件，像素去重2728/4050。精确去重只能剔除完全同图，不能得出设计数量。
2. 本次使用现有静态声明解析器复核：69份general/npcs文件中的336个字面名字；zones/*/npcs.lua共269次声明、252个不同名字。两组重叠9个，合并579个不同字面名字。范围与字段来源见base-family-index.csv和base-zone-index.csv。该结果包含普通NPC/独特角色，不是579个必需独立物种：共享外观、同一角色别名、改名/生成器和动态召唤需要进一步解析，脚本也可能漏掉翻译/运行生成名字。
3. 本体角色据此围绕约600的规模预留500–650个设计，允许可信身份复用，同时保留高图/特殊形态/独特角色增量。DLC增加的190个NPC文件不能机械地等同190种新怪；按新增族系和特殊构装体，暂预留总650–850。尚未完成全DLC身份解析，这一栏不属于精确覆盖统计。
4. 地形从29共享Grid脚本/89本体区域组织成套件。一般地面、墙体、树、水、开闭门等复用少量母版；地图/地区回调决定危险与交互，而非每PNG独立设计。预留约120–200项通用套件设计，加约80–100项特殊构件、材质变体、地标、城镇/世界图及交互入口，形成200–300的本体预算。DLC素材继续复用，再预留50–100项，得到250–400。
5. 多方向照明、特殊动态规则可能需要额外状态图；反之通用透明构件、方向标记与邻接导出可减少手绘。要在各套件样板通过后修订估算，不声称所有地形都已经证明可压缩到此范围。

## 与调用次数/运行文件数的区别

700–950/900–1,250是计划设计总量。一次成功通常对应一张原图；局部返修、多次失败会增加调用次数。现有C0四款各一次通过仅是小样本，不能据此承诺全游戏100%一次通过。运行文件还包括尺寸、邻接、开关状态、透明叠层和UI程序资源，数量会明显更多。

现有Kor’Pul 6母版派生196张地形PNG，是减少绘制量的已验证案例；不能把这个32.7倍比例套到全游戏所有地形。

若未来增加全物品重绘，可参考原库本体706/含DLC977文件重新分族；技能图标1347/1776文件亦需另立工作包。它们目前不在上表中，也不能未经语义审计直接作为新增母版数相加。完整换装仍是另一项规模远大的项目。
