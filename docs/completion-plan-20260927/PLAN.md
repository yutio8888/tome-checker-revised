## 4. 模板与脚本怎样减少消耗

已经实现[生产目录](../../art/production/README.md)和[任务脚本](../../tools/art_tasks.py)：

1. 主代理/源码代理一次核实身份和显示合同，钉住来源、参考图和证据哈希。子代理拿1–4个小任务及所需文件，不重复整段历史或全目录审阅。哈希变化才重新核对相关输入。
2. 固定相机、底座、光向、透明边界和禁用UI层；变量只有身份造型、剪影/明度、材质、必要规则。每款1张风格＋1张原生图，最多再加1张同族参照。子代理仍须实际看图；哈希校验不能代替视觉判断。
3. 新家族先出1款锚点，再做最容易混淆的对照款；通过48/64/96px同屏和灰度判断才展开。同族至少在剪影/明度/色相中两项不同。候选一次一图，不让AI画整张atlas再切割。
4. 每款默认首轮1次＋至多1次有明确缺陷的定向返修。第二次仍失败就交回设计，不连抽；脚本记录尝试与实际提示，不自动判“美观合格”。新一轮预算由主代理记录，不能换目录把历史失败清零。
5. 邻接16掩码、棋盘明暗、透明前景叠地板、尺寸导出、运行圆环/角标用既有程序生成。光照有方向的构件不可为了省图随意旋转。怪物的不同物种不能只做换色。
6. 脚本不调用付费API，不创建API key，不替代内置ImageGen。它只生成任务文件及校验原图；实际调用由子代理遵循imagegen技能完成。没有合法size/quality/seed工具参数可供脚本强制控制；1024只是提示请求，实际尺寸据输出记录。

这能直接减少重复阅读、重复身份出图、过早给不支持的对象出图和返修次数；**不承诺固定节省百分比，也不把多开子代理当成免费提速**。每批记录：授权身份数、实际调用数、首次通过数、返修原因、已接入数。以累计“调用数/已接入身份”和首轮通过率调节批量。

## 5. 分工、测试与完成定义

- **gpt-6-sol：**确定性清单/来源比对、模板填参、任务打包、既有导出、哈希/alpha/边界检查；成熟家族可按已经锁定的造型任务调用ImageGen，不自行重设风格或扩大身份匹配。
- **Astra：**新家族造型与关键对照、复杂首领/地形构件、ImageGen难图及返修方向；高图/动画/shader、召唤复制、动态地形和可信身份改名合同。
- **主代理：**验收小尺寸和同族差异，维护唯一台账、集成、实机、提交。美术代理只写独立批目录；运行代码由一个集成人修改。先完成一个家族锚点再并行，通常2个工作代理足够。

验证分层：每图保存原始母版、完整提示和来源，查alpha/尺寸/边界；每批做48/64/96静态同族审阅；普通已支持身份做目标映射回归＋1920×1080两变体场景。增加高图/shader/地形行为等机制时才跑相应完整回归，不能每加一只普通鼠都重拍全部楼梯17图。里程碑再做Board/Minimalist冷启动独立性、跨进程整局读档、实际移动/击退/召唤混战、复杂状态和48px密集场景。截图、日志和测试结果分开记录；测试夹具摆位不能冒充自然遭遇。

HUD维持0.2.4，服务于这些样本验收：复杂资源/效果、日志密度、窄屏、聊天状态按场景补证。不重画大量技能图标；不把完整Minimalist主题插入怪物扩库关键路径。

**建议下一轮具体交付：**先解析并完成C0首批4怪，保持同族差异；同时由复杂任务代理完成G0普通/硬树和两种水的规则清单。随后推进Kor’Pul两首领及封门、森林泛滥与方向出口。每完成一个经过验证的小批就提交，计划状态不能代替运行交付。
